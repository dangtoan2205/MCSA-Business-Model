NPS sẽ sử dụng **Active Directory làm cơ sở xác thực**, còn Cisco 2960S là **RADIUS client/NAS**. Microsoft xác nhận switch 802.1X là RADIUS client, không phải máy PC.

# 2. Một lưu ý rất quan trọng

Có một điểm cần làm rõ với mục tiêu ban đầu:

>**Join Domain ≠ tự động được cấp Internet.**

AD có nhiệm vụ:

- quản lý tài khoản;
- quản lý máy tính;
- xác thực;
- GPO;
- phân quyền.

NPS/802.1X có nhiệm vụ:

- xác thực thiết bị/người dùng khi kết nối mạng;
- quyết định cho phép hoặc từ chối truy cập mạng;
- có thể trả về VLAN theo chính sách.

pfSense có nhiệm vụ:

- Gateway;
- Firewall;
- NAT;
- Internet policy;
- inter-VLAN routing nếu bạn thiết kế routing trên pfSense.

Do đó, kiến trúc doanh nghiệp sẽ là:
```
AD
 │
 ├── User
 ├── Computer
 ├── Group
 └── GPO
       │
       ▼
      NPS
       │
       │ RADIUS
       ▼
 Cisco 2960S
       │
       │ 802.1X
       ▼
      PC
       │
       ▼
    VLAN
       │
       ▼
   pfSense
       │
       ▼
   INTERNET
```

# 29. Cấu hình RADIUS trên Cisco

Ví dụ NPS:
```
192.168.90.10
```
Cisco:
```
enable
configure terminal
```
Bật AAA:
```
aaa new-model
```
Khai báo RADIUS:
```
radius-server host 192.168.90.10 auth-port 1812 acct-port 1813 key <YOUR-RADIUS-SECRET>
```
Sau đó:
```
aaa authentication dot1x default group radius
```
và:
```
aaa authorization network default group radius
```
Cuối cùng:
```
dot1x system-auth-control
```
Đây là các thành phần Cisco sử dụng để bật 802.1X và chỉ định RADIUS làm phương thức xác thực.

# 36. Nhưng chưa kết thúc ở đây

Có một vấn đề rất quan trọng liên quan đến yêu cầu ban đầu của bạn:

> **"Tất cả máy phải Join Domain thì mới được Internet."**

Nếu chỉ dùng:
```
User → username/password → NPS
```
thì chưa chứng minh được **máy tính đã Join Domain**.

Một người có thể dùng tài khoản domain trên một máy không thuộc domain nếu chính sách EAP cho phép kiểu xác thực đó.

Để kiểm soát thiết bị **domain-joined**, mô hình tốt hơn là:
```
Domain Computer
       │
       ▼
Computer Certificate
       │
       ▼
EAP-TLS
       │
       ▼
NPS
       │
       ▼
Computer Authentication
       │
       ▼
Cisco 802.1X
       │
       ▼
VLAN
```
Do đó **bước tiếp theo mình khuyên không phải là mở rộng 802.1X ngay**, mà là xây **AD CS/PKI** để cấp certificate tự động cho các máy đã Join Domain.
